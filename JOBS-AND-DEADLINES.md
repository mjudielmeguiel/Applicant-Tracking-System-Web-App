# Jobs, requirements activity and deadlines

Job Openings replaces MRF Monitoring. Use /job-openings; old /mrf and /mrf-monitoring.html URLs redirect there. The original mrf-monitoring.html filename now contains the job-opening screen. Retired MRF scripts are excluded from published assets.

The MRF_Monitoring table and its 1,329 rows were removed as explicitly requested, along with 1,520 archived MRF workbook rows and MRF-specific list/save/context RPCs. Shared positions, locations, applicant imports, all 741 existing applicants and job counts were preserved. The internal mrf_owner helper remains because it verifies workspace ownership for existing custom-session APIs; it does not query MRF data.

HR users and admins can Post job, search title/location/description, and view Available, Occupied or All openings. Dashboard openings appear on the right and default to available jobs only. Each opening has position, location, description, total slots, posting user and checked document requirements. The posting HR user or admin can edit it. Use Occupied to close an opening; there is no destructive delete control. Position and location lock once applicants exist.

Counts derive from real applicant records under the same AdminID and position/site. Hired and Deployed occupy slots. Applicants linked to JobOpeningID count directly; legacy applicants match by position and site. Available slots are total minus filled, clamped to zero; an Occupied opening has zero available slots. No fake hires were inserted.

Three other postings are Occupied: Inventory Analyst–ZABARTE, Reach Truck / Forklift Operator–PASIG - SHELL, Site Engineer–NAVOTAS. Existing filled counts are included in each total; job descriptions and document checkboxes are editable.

The dashboard Requirements activity panel records uploads, review changes, overdue deadlines and renewed windows. It refreshes every 30 seconds while visible and is filtered by the verified session's AdminID.

Applicant personal details are optional, while an opening must be chosen. Requirements deadlines allow 1–7 days from the first opening. On expiry, uploads close and requirements become overdue for HR review; hiring status is unchanged. See APPLICANT-INVITATIONS.md.

Validation: production build; browser checks for navigation, job search/post/edit/document checkboxes, mobile layout, invitation settings, optional personal fields, branded combined jobs, autosave, document reviews/replacements, overdue/reopening; rollback-only database checks for owner isolation, actual counts, selected-job requirements, expiry and renewal. SQL tests leave no applicant or invitation records behind.

Job Openings now uses one table grouped by position, with locations listed under each position. Each location includes a saved site address, available and occupied slots, and links to Hired/Deployed applicants occupying those slots. The Occupied filter includes partially filled openings. A manually closed opening does not invent occupant records. Use Add location to post another location under the same position. Apply supabase-job-locations.sql after the other current migrations. Public applicant links receive the job address but never the staff-only occupant list. Existing addresses stay blank until HR provides them.

The final consolidation migration is supabase-unified-job-opening.sql (apply last). The single authoritative table is public."Job_Opening". It holds position, site, address, description, slots and requirements together. public.positions, public.location and the former private job_openings table no longer exist. Existing opening IDs and applicant/invitation ownership foreign keys were preserved. Dropdown choices are derived from Job_Opening and existing applicant history, rather than separate catalog tables. Source settings remain separate. All position/location creation happens through Post job / Add location on Job Openings. Sidebar links use the existing mrf-monitoring.html compatibility file, which opens directly from the project folder or redirects to /job-openings when hosted by Next.js. Do not type file:///C:/job-openings; that is not an HTML file.
